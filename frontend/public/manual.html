01The problem

Two facts drive nearly every decision in this codebase. Both are about the data, not the code.

No single free trail dataset is good enough

Each source holds one piece. USFS has geometry and allowed-use but no national parks. NPS has parks but no forests. Neither has regional or county land — which is where most Californians actually walk. Nobody has elevation. The product is the conflation. That is also why “there is no good free trail data” feels true: the pieces exist, but nobody hands you them joined.

No dataset models a hike

Every source publishes trail segments, because segments are what agencies administer and budget against. “Half Dome is a 14-mile hike from Happy Isles” is a visitor-facing composition no land manager has an operational reason to record — which is why OpenStreetMap also models Half Dome Trail as 2.00 mi. The absence is structural, so composition has to be computed. That is what the routing graph exists for.

Missing is never rendered as a value.

Every check reports ok or unavailable. The risk engine has an incomplete state that cannot render green. A gain filter excludes a trail whose elevation is unknown rather than treating it as flat. Unknown gain returns None, never 0.

Most bugs found in this codebase have been violations of this rule.

The split is deliberate: trail data is a build artefact, user data is a database. Trail data is read-only, regenerated wholesale, and versioned with the index. Postgres holds what is genuinely relational and mutable. Putting the index in Postgres would make every rebuild a data migration.

03Build pipeline

python -m pipeline.build_index — stages are skippable and resumable. Numbered because this genuinely is a sequence: later stages read what earlier ones wrote.

  1. 01normalize
    12,315 USFS segments → 8,162 trails, grouped by TRAIL_CN
  2. 02nps
    Park trails, plus the opt-in SEKI fallback that carries Mount Whitney
  3. 03osm-routes
    Long-distance route=hiking relations ≥ 5 mi
  4. 04osm-trails
    Named OSM ways → trails on regional, county and state park land
  5. 05elevation
    DEM sampling at one reading per 0.05 mi; gain via hysteresis walk
  6. 06scenery
    GNIS named features + OSM POIs, joined by proximity
  7. 07access
    Trailheads, parking, water and camping from NPS + USFS + OSM
  8. 08technical
    sac_scale and trail_visibility badges
  9. 09permits
    Recreation.gov permit facilities, joined by proximity
  10. 10wilderness
    Point-in-polygon land status against 88 designated areas
  11. 11markers
    The point to draw for each trail — must run after access

Three sweeps are not build stages

Each takes roughly an hour against rate-limited public mirrors, so none of them may hide inside a build. Output is cached per tile and resumes cleanly. 

python -m pipeline.osm_access    # access points → data/osm_access_points.json
python -m pipeline.osm_trails    # named ways    → data/osm_ways.json
python -m pipeline.geom_store    # LOD geometry  → data/trails_geom.sqlite

access.py compares mtimes against the sweep output. A version check alone was not enough: the cache gets written before the sweep exists, so a matching version would have made the app ignore the sweep’s results permanently.

Two points that mean different things

center — a bounding-box midpoint

Correct for fitting a viewport, and wrong for drawing. Measured across the index, 13.2% sit more than 0.25 mi off their own trail; the worst is 4.71 mi out, which points at a different valley.

marker — what the map actually draws

The joined trailhead where one exists (19.9%), otherwise the vertex at half the trail’s length. Median distance from the trail: 0.

Activity is partly published, partly derived

hiking: allowed is true for 11,150 of the 11,150 trails carrying use data, so it separates nothing. What separates a trail from a road is whether motors are allowed on it — and USFS publishes that, so no hand labelling is needed. “Rubicon Jeep” carries fourwd + atv + motorcycle and excludes itself.

Silence is not evidence: 18.9% of the index has no allowed-use data at all, and treating that as motorised would drop most of the NPS set out of every hiking search.

05Serving & performance

Facets count over the right pool

Each filter is a named predicate, and facet counts are computed over a pool with that filter’s own dimension excluded. A chip therefore shows “how many results choosing this would give”, not “how many survive the choices already made” — counting over the fully-filtered set makes selecting one filter grey out every other.

The map: dots, then lines

ZoomEndpointPayload
< 11/api/discover/dots73 KB
≥ 11/api/discover/map?detail=z12265 KB

Dots are the important case. marker lives in the search index, so the dots path never calls load_geometry() — and dots are fetched once per filter set rather than per pan, so panning and zooming become pure client work.

06Routing graph

The answer to “no dataset models a hike”. Snap every vertex to a 4 m grid; any shared point is a junction. Split trails at junctions into edges. Weight by length and directional gain. Then run Dijkstra over 214,852 nodes and 441,213 edges. A hike becomes a path: trailhead → destination → back.

RouteComputedPublished
Half Dome, from Happy Isles13.88 mi / 5,245 ft~15 mi / 4,800 ft
Nevada Fall, from Happy Isles5.5 mi / 2,176 ft~5.4 mi / 1,900 ft
Ryan Mountain2.8 mi / 1,054 ft~3 mi / 1,050 ft

Half Dome indexes as a 2.00 mi segment and composes to a 13.88 mi hike. That gap is the entire point.

Four things that had to be right, each wrong first

Node identity must be tight — 4 m

Loose snapping fused adjacent switchback legs and let the router cut straight up Whitney: 8.6 mi against a true 22.

Tight snapping alone disconnects the network

Agencies do not share coordinates where their trails meet. A separate pass stitches endpoints within 35 m; stitching mid-trail vertices would reintroduce the fusion.

Gain is computed once along the finished path

Never summed per edge. Nodes are metres apart, so per-edge accumulation counted DEM noise as climb and reported Whitney at 14,232 ft.

nearest_node must size its search from max_miles

A hardcoded ±3 cells spanned 60 m at 20 m snapping but only 12 m at 4 m, so trailheads silently resolved to no node and routes returned “no path”.

Concurrent routes, and why legs are merged

Long-distance relations are mapped over the same ground as the local trails they follow, so consecutive edges flip between two records: a 17.8 mi hike came back as 80 legs alternating every 0.02 mi. Collapsing consecutive duplicates cannot help when the sequence is A,B,A,B. Legs shorter than a stride (0.15 mi) are absorbed into their larger neighbour, shortest first — 80 legs became 8, with mileage preserved exactly.

The cost, and it is real

Build time~55 sBlocks every other request — CPU-bound Python in one worker
Resident memory~1.8 GBMore than the rest of the process combined
Warm query~25 msOnce built, it is fast

GRAPH_PREWARM=1 moves the stall into container startup. It is off by default because on a 1 GB VPS the memory alone is fatal. Precomputing the graph to disk is the real fix, and the top open item.

The trap in each one

USFS — lowercase property names

Fields are trail_cn, trail_name, segment_length. An earlier loader read uppercase and returned zero trails. Values are also dual-encoded (12-20% and TG05 - +12-20%), and N/A, None and "" all mean missing.

USFS INFRA — there is no trailheads layer

Trailheads are a site_type inside EDW_RecInfraRecreationSites_02, which is why searching EDW for a trailheads layer finds nothing. Absence also arrives as the string "No Data", not null.

NPS — Sequoia & Kings Canyon returns zero

Verified by both a unit query and a spatial query, so Mount Whitney is otherwise absent entirely. The fallback is a third-party rehost with unconfirmed provenance, so it is opt-in and every record it produces stays labelled rather than passing as NPS-authoritative.

OSM ways — the largest gap, and a structural one

Both agency sources are federal. Measured on the South Bay before this source existed: 15 trails in the index against 4,415 named OSM ways. Sierra Azul, Almaden Quicksilver, Santa Teresa and Castle Rock were all missing, because MROSD, EBRPD and Santa Clara County Parks publish to neither USFS nor NPS.

OSM POIs — stage_osm only fetches when the file is absent

Once pois.json exists the --with-osm branch is unreachable, which is why an OSM supplement never entered a resumed build. Scenery was GNIS-only, and viewpoint, cave and glacier were missing entirely.

RIDB — /permitentrances is the wrong endpoint

It looks obvious and is not: 907 nationally but only 34 in California, named as opaque codes, with no Half Dome or Whitney at all. Permits are modelled as facilities with FacilityTypeDescription == "Permit" — only 7 in California, but precisely the ones that gate California hiking.

OSM access — natural=spring is deliberately excluded

Despite 17,384 statewide. A spring is untreated and may be seasonal, and promoting it to drinking water would tell a hiker there is water where there may be none. Parking is admitted only when the name says trailhead, or every supermarket car park qualifies.

DEM — summing positive deltas invents climb

In testing, ±8 ft of sampling noise over 400 samples produced 1,050 ft of phantom gain. Gain uses a hysteresis walk with a 15 ft threshold, validated against Mt Whitney: sampled 14,477 ft against a true 14,505 ft.

Stubbed, not active

Carrier coverage tiles (T-Mobile, AT&T, Verizon) appear in planner_api.py as empty strings with commented example URL patterns. No carrier publishes a documented tile API; nothing is fetched.

Licensing position

ODbL applies to all OpenStreetMap-derived data. This project is personal-use and undistributed, so share-alike does not trigger. If that changes, attribute OpenStreetMap contributors — the index already declares its provenance as USFS National Forest + NPS Public Trails + SEKI + OpenStreetMap (California).

08Deployment

Two compose files, and the difference matters more than it looks.

 docker-compose.local.ymldocker-compose.yml
Backend portPublished on 6767Not published — nginx proxies
./dataBind-mountedNot mounted

.dockerignore deliberately excludes data/ from the image — the index plus source is ~330 MB and has no business inside a layer. docker-compose.yml therefore has no path to an index and 503s every discovery route. Use the local file: 

docker compose -f docker-compose.local.yml up -d --build

App source and the frontend bundle are baked into images, so code changes need --build, not a restart. Data is bind-mounted, so an index rebuild needs only a restart — but load_index() caches into a module global, so a restart is required. nginx gzips, and gzip_proxied any matters: API responses come back through proxy_pass and are otherwise skipped.

09Known limits

  • Segmentation is not a data problem. Verified across RIDB, NPS, OSM, Hiking Project and GPX corpora. Hence the graph.
  • The routing graph is not persisted — 55 s build, 1.8 GB resident, blocks other requests while building.
  • OSM way coverage is Bay Area only. Los Angeles, San Diego and Sacramento have the same gap and need the same sweep.
  • Surface missing on 21.4%. Filling it needs way-level matching via a 1.2 GB Geofabrik extract — disproportionate so far.
  • Fire filtering is by centroid, not true spatial intersection.
  • Weather and AQI are point lookups, not route-aware.
  • The conditions cache is process-local — no persistence, no sharing across workers.
  • sac_scale is a badge, never a facet — 0.3% coverage, and a filter dropping 99.7% of the index is worse than no filter.
  • Mobile is “not squished”, not designed. React Native is the honest answer if it becomes a real target.

Testing

200 tests, about 0.2 s, no network and no index load. They encode the traps above rather than the happy path: DEM noise not becoming gain, "No Data" not becoming a value, an unmappable trail not being reported as truncation, dots never loading geometry, a jeep road never being a backpacking route.

tests/test_api_wiring.py walks the AST of every route handler and asserts each name it reads is actually bound. It was added after a global string replace introduced NameError: name 'detail' is not defined into the photos endpoint — a 500 that no test touched, because those endpoints need the real index to exercise.
